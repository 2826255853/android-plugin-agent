# 阶段 D.1 候选包交付契约

候选包 v1 以[阶段 3.1 的 `delivery.json`](../阶段3.1交付与导入.md)为字段基础。回执引用[阶段 C.7 的成功快照](../阶段C.7端到端验收.md)，电脑向指定配对设备发布，Android 主动查询和分段拉取。C.7 的构建记录继续以 `built / deliverable: false` 表示构建结果。现有手动交付目录按阶段 3.1 的契约读取。

## 回执与信任来源

| 字段 | 约定 |
| --- | --- |
| `deliveryVersion`、`type` | 整数 `1` 和 `delivery.receipt`。所有 JSON 操作沿用同一版本字段。 |
| `deliveryId` | 电脑生成的小写 UUID。同一交付 ID 的回执不可变。 |
| `sourceFingerprint`、`deviceId`、`credentialId` | 来源电脑已固定的 TLS 证书 SHA-256、目标 Android 设备 ID 与该次配对凭据 ID。设备名称用于展示，认证使用配对连接。重新配对产生新的凭据 ID。 |
| `projectId`、`taskId`、`buildId` | 现有项目 ID、任务 ID 及正整数构建序号，构建序号上限为 JSON 安全整数上限。 |
| `specVersion`、`specSha256` | 正整数规格版本（最大 2,147,483,647）和不可变确认规格的摘要。 |
| `pluginId`、`pluginName`、`pluginVersion`、`hostApi` | 取自同一快照中的清单。名称最长 64 个 UTF-16 代码单元。版本为三段稳定版号，最长 32 字符。`hostApi.min` 和 `hostApi.max` 同主版本，按数值比较并包含两端。设备兼容性在 D.5 结合实际宿主 API 校验。 |
| `checks` | 五项必需结果都为布尔值 `true`。`static` 表示静态检查全通过，`packaging` 表示确定性打包和回读通过，其余为 `isolatedBuild`、`isolatedTest`、`interactivePreview`。电脑从 C.7 报告映射结果，并只发送这些固定字段。 |
| `manifestSha256`、`packageFile`、`sizeBytes`、`packageSha256` | 原始清单摘要、`<pluginId>-<pluginVersion>.zip`、原始 ZIP 的大小（1–10,485,760 字节）及摘要。所有 SHA-256 为 64 位小写十六进制。文件名用于展示，存储路径由宿主生成。 |
| `offeredAt`、`expiresAt` | UTC 时间，后缀 `Z`，可有 1–6 位小数秒。有效期大于零且最长 24 小时，以更早到期的配对凭据期限为界。到达 `expiresAt` 即过期。 |

电脑发布前从可信任务仓储核对请求中的项目、任务、构建序号和包摘要，读取原始快照、确认规格、清单和检查报告。Android 从已认证连接和本地项目取得期望的来源、设备、凭据和项目，逐项核对回执，并按本机当前时间检查有效期。电脑在每次网络请求时按服务端时间和当前配对状态授权。回执的来源证明来自既有 TLS 1.3 固定指纹连接和配对认证。

JSON 使用 UTF-8，单条请求及 JSON 响应上限为 128 KiB。拒绝未知字段、重复键、错误类型及未知版本。整数使用 JSON 整数字面量。[JSON Schema](delivery.schema.json)描述线格式，两端解析器进一步校验字段关系、UTC 日期、名称长度、作用域、有效期和范围。

## 操作与重试

| 请求 | 入口与参数 | 成功响应 |
| --- | --- | --- |
| `delivery.publish` | 电脑本地控制入口。提供来源指纹、设备 ID、凭据 ID、项目 ID、任务 ID、构建 ID 和包摘要。 | `delivery.published` 携带完整 `receipt`。 |
| `delivery.query` | `POST /v1/delivery/query`。提供 `projectId`、`after` 及 `limit`（1–20）。 | HTTP 200，`delivery.page` 回显 `projectId`、`after`，包含 `receipts` 和 `hasMore`。 |
| `delivery.lookup` | `POST /v1/delivery/lookup`。提供 `projectId` 和 `deliveryId`，供恢复下载和确认导入时重新检查。 | HTTP 200，`delivery.found` 携带完整 `receipt`。 |
| `delivery.download` | `POST /v1/delivery/download`。提供 `projectId`、`deliveryId`、`packageSha256`、零基 `offset` 和 `length`（1–262,144 字节）。 | HTTP 206 和指定范围的原始 ZIP 字节。 |
| `delivery.revoke` | 电脑本地控制入口。提供 `deliveryId`。 | `delivery.revoked` 回显交付 ID。撤销后的新请求读取不到候选包。 |

所有请求提供小写 UUID `requestId`。JSON 响应回显该字段。网络接口使用既有 `Authorization: Bearer …` 和 `X-Credential-Id` 请求头，由服务端从认证记录导出设备身份。服务端先认证，再按设备、凭据和请求项目查找交付。身份或项目越界的直接查询与下载统一返回 `DELIVERY_NOT_FOUND`。撤销配对后旧凭据失效，受其绑定的候选不能由新凭据领取。发布和撤销由本地入口授权。

分页按 `deliveryId` 字典序升序。首个 `after` 为空字符串，后续使用前一页最后一个 ID 作排他游标。仅列出有效候选，`hasMore: true` 时返回满页。列表反映每次查询时的有效记录。新发布可能落在已读区间，刷新时从首屏开始。Android 按 `deliveryId` 去重。单条查询的错误用于判定过期和撤销，列表遗漏只触发重新查询。

下载要求 `offset + length <= sizeBytes`，超范围按原请求拒绝。HTTP 206 响应携带 `Content-Type: application/octet-stream`、`Content-Range: bytes <offset>-<offset+length-1>/<sizeBytes>`、`Content-Length: <length>`、`ETag: "<packageSha256>"`、`X-Delivery-Id` 和 `X-Delivery-Request-Id`，禁用压缩和重定向。客户端只在核对全部响应头且读足声明字节后提交片段与持久偏移，截断或超量的片段丢弃。中断后重新查询同一回执、复核已落盘长度并从最后提交的偏移续传。重试同一片段使用原请求 ID，新字节范围生成新请求 ID。查询和下载是只读请求，每次重试重新检查当前授权。

电脑按操作和请求 ID 持久保存发布及撤销结果。相同内容的重试返回原回执或原撤销结果，重复发布的历史回执依旧按当前有效性核对。相同操作与 ID 携带不同内容返回 `REQUEST_ID_CONFLICT`。发布结果、回执和交付状态须原子保存。撤销或过期后如需再次交付，使用新请求 ID 发布并获发新的交付 ID。

失败响应为 `delivery.error`，使用 `code` 和原请求 ID。无法解析请求 ID 的格式错误可沿用 A.1 的传输错误响应，客户端禁止将其解释为操作结果。

| HTTP 状态 | 错误码 |
| --- | --- |
| 400 | `INVALID_REQUEST`、`UNSUPPORTED_SCHEMA_VERSION` |
| 401 / 403 | `AUTH_REQUIRED` / `DEVICE_REVOKED` |
| 404 | `DELIVERY_NOT_FOUND` |
| 409 | `REQUEST_ID_CONFLICT`、`DELIVERY_BINDING_MISMATCH` |
| 410 | `DELIVERY_EXPIRED`、`DELIVERY_REVOKED` |
| 413 / 416 | `PAYLOAD_TOO_LARGE` / `DELIVERY_RANGE_INVALID` |
| 429 / 500 | `RATE_LIMITED` / `INTERNAL_ERROR` |

本地发布遇到未通过必需检查或不存在的快照时返回 `BUILD_NOT_AVAILABLE`。连接中断、超时、限流和暂时性服务错误可按原请求重试，限流遵循 `Retry-After`。认证、绑定、过期、撤销和格式错误须处理原因后才能发起新操作。网络错误只传稳定代码。

## 状态与记录方

| 记录方 | 前置状态 → 新状态 | 事实与本地事件 |
| --- | --- | --- |
| 电脑 | `built → offered` | `publish` 持久保存定向回执。构建状态继续由任务仓储管理。 |
| Android | `unseen → offered` | `observe` 首次保存已核对的候选回执。 |
| Android | `offered → interrupted → offered` | `disconnect` 保留最后提交的字节偏移，`resume` 在重新查询并核对回执和暂存后恢复。 |
| Android | `offered → transferred` | `receive_all` 确认全部字节已落盘。 |
| Android | `transferred → verified` | `verify` 校验整包大小和 SHA-256，校验清单摘要及身份、版本、API 范围，并通过宿主包和兼容性检查。 |
| Android | `verified → imported` | `commit_import` 仅由用户针对该回执确认后触发。重新检查候选有效性，交同一份私有 ZIP 给现有导入器，以导入器的持久化成功结果为准。 |
| Android | `transferred` 或 `verified → rejected` | `reject` 保存稳定原因。已收齐阶段支持 `package_hash_mismatch`、`plugin_identity_mismatch`、`incompatible_host_api`、`invalid_package`。已校验阶段支持 `user_declined`、`import_failed`。导入结果不确定时先核查安装记录。 |
| Android | 处理中 → `cancelled` | `cancel` 表示用户取消下载或关闭本次导入流程，清理对应暂存。用户明确拒绝审阅结果使用 `rejected`。 |
| 电脑与 Android | 处理中 → `expired` 或 `revoked` | `expire` 记录到达有效期，`revoke` 记录权威撤销或当前配对撤销。电脑只从 `offered` 更新，Android 在收到结果或本机确认过期后更新并清理暂存。 |

处理中包括 `offered`、`interrupted`、`transferred` 和 `verified`。两端各自持久保存状态和最后已提交的恢复证据。事件按交付 ID、记录方与事件 UUID 去重，原事件与状态变更一并提交。相同事件重放返回当前状态，变更有效事件的内容返回 `EVENT_ID_CONFLICT`，非法跳转返回 `INVALID_STATE`。终态为 `imported`、`rejected`、`cancelled`、`expired` 和 `revoked`。网络响应、下载收齐和完整性验证分别提供各自的证据，安装成功只来自 Android 导入器已提交的结果。

阶段 E 可据本地导入结果定义安装回执，关联 `deliveryId`、配对身份、项目、任务、构建、插件 ID/版本、包摘要、结果和时间。D.1 的操作不接收设备安装结果，跨端同步由阶段 E 接入。

## 复现

```powershell
python scripts/verify-stage-d1.py
python scripts/verify-stage15.py --serial emulator-5554
```

配备可选验证工具 `jsonschema` 的环境可运行 `python scripts/verify-stage-d1.py --schema`，同时检查 Schema 和样例形状。

Python 和 Android instrumentation 读取同一份[虚构夹具](fixtures/stage-d1.json)。覆盖回执形状、错误来源和目标、凭据轮换、缺字段、大小和摘要、有效期边界、响应关联、续传范围、事件重放及非法跳转。发布持久化、网络端点、断点续传和导入流程由 D.2–D.7 接入并验收。

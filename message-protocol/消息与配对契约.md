# 手机到电脑消息与配对契约 v1

阶段 A.1 已冻结本契约，A.2 实现了电脑接收服务和 HTTPS 传输，A.3 实现了持久回执。详见 [阶段 A.2 电脑接收服务](../阶段A.2电脑接收服务.md) 和 [阶段 A.3 持久收件箱](../阶段A.3持久收件箱.md)。

机器校验入口是 [`message.schema.json`](message.schema.json)。固定夹具位于 [`fixtures/`](fixtures)，Python 回归入口是 `python scripts/verify-message-protocol.py`，Android 解析器是 `MessageProtocol.kt`。夹具中的所有设备、项目、密钥指纹和正文均为虚构值。

## 1. 传输和信任边界

- 接收服务只使用用户明确选择的局域网接口，提供 TLS 1.3 HTTPS。服务停止后关闭监听端口，连接和请求均失败；重新启动不会自动扩大监听范围。
- Android 在首次配对前校验电脑显示的服务器证书 SHA-256 指纹。配对申请携带一次性六位配对码，配对码只在桌面端界面和 TLS 连接中短时存在，不能写入普通日志。
- 电脑端必须显示设备名称、设备 ID、证书指纹和配对申请的过期时间，由用户明确确认。未确认的申请不产生凭据。
- 确认后，电脑端生成随机凭据 ID 和一次性凭据，通过当前已认证的 TLS 配对响应交给 Android。电脑端只在操作系统受保护的凭据存储中保存凭据的验证材料。Android 只把凭据放进 Android Keystore 保护的本地存储。
- 后续消息同时使用 TLS 1.3 和配对凭据认证。凭据只允许消息接收和状态查询，不能访问任务创建、文件、命令、插件生成、构建或交付接口。
- 撤销在电脑端立即生效，已建立连接也必须在下一次请求时被拒绝。服务停止只关闭服务，不等同于撤销设备；重启后仍按已配对列表恢复，除非凭据已过期或撤销。

## 2. JSON 通用规则

- 所有请求和响应使用 UTF-8 JSON 对象，根对象和嵌套对象均拒绝未知字段、重复键、BOM、尾随内容、非标准数字和错误类型。协议版本固定为 `schemaVersion: 1`，未知版本返回 `UNSUPPORTED_SCHEMA_VERSION`。
- 请求体编码后最多 128 KiB。用户正文最多 12,000 个 Unicode 字符，不能为空。`bodySha256` 是正文 UTF-8 字节的 SHA-256 小写十六进制摘要，服务端必须重新计算并比对。
- 时间戳使用 UTC 的 RFC 3339 子集 `YYYY-MM-DDTHH:MM:SS[.ffffff]Z`。电脑端按服务接收时间记录回执，不采用客户端时间替代服务器时间。
- `projectId` 沿用现有规格格式 `[a-z][a-z0-9-]{2,63}`。`messageId`、`requestId` 和 `credentialId` 使用小写 UUID。消息序号从 1 开始，在同一设备和项目内递增。
- 任何重试都沿用原 `messageId`、创建时间、项目 ID、序号、消息类型、正文、正文摘要和可选规格字段。相同设备、相同消息 ID 且业务字段一致时返回原回执。相同消息 ID 对应不同项目、序号、类型、正文、正文摘要或可选规格字段时返回 `MESSAGE_ID_CONFLICT`。同一设备在同一项目中以不同消息 ID 使用已占用的序号时返回 `MESSAGE_SEQUENCE_CONFLICT`。
- 客户端在消息创建时间起 24 小时内重试。服务端超出窗口返回 `RETRY_WINDOW_EXPIRED`。限流和暂时性服务失败返回 `retryable: true` 及可选的 `retryAfterSeconds`，认证失败、撤销和格式错误不可重试。

## 3. 操作结构

每个操作的完整字段、类型和未知字段规则以 Schema 为准。下面只列出语义和状态。

| 操作 | 方向 | 语义 |
| --- | --- | --- |
| `pair.request` | Android → 电脑 | 创建 10 分钟有效的一次性配对申请，绑定设备 ID、设备名称、客户端密钥指纹和配对码。 |
| `pair.confirm` | 电脑 → Android | 用户确认后返回服务器证书指纹和配对凭据，或返回拒绝原因。凭据只在配对响应中出现。 |
| `pair.revoke` | 电脑 → 电脑服务 | 撤销指定设备和凭据，支持用户主动移除、凭据泄露和移除设备三种原因。 |
| `pair.revoked` | 电脑 → Android | 告知 Android 凭据已撤销，客户端停止自动发送并要求重新配对。 |
| `message.send` | Android → 电脑 | 发送一条用户消息。阶段 A 只进入电脑收件箱，不创建规格、任务或生成操作。 |
| `message.receipt` | 电脑 → Android | 表示消息已持久化或已按相同 ID 幂等处理。`received` 和 `duplicate` 均为不可重试的最终接收结果。 |
| `status.query` | Android → 电脑 | 查询单个消息的持久化状态。 |
| `status.response` | 电脑 → Android | 返回 `queued`、`received`、`failed_retryable`、`rejected` 或 `revoked` 状态。 |
| `error` | 电脑 → Android | 返回稳定错误码和重试属性，不返回绝对路径、凭据、底层网络错误或未筛选日志。 |

`message.send.messageType` 当前允许 `user.message`、`user.answer` 和 `user.confirmation`。阶段 A 不解释这些正文，也不把 `user.confirmation` 当作规格确认；B 阶段接入规格流程后再定义其业务语义。`specVersion` 与 `confirmation` 仅用于保持消息兼容性，未接入 B 前不得触发任务。

A.3 在事务提交后以 HTTP 200 返回 `message.receipt`，状态为 `received`。幂等重发沿用原回执的 `requestId`、`createdAt` 和 `receivedAt`，`inReplyTo` 指向本次请求。回执丢失后，设备可重发原消息或用 `status.query` 查询 `received` 状态和原接收时间。重试窗口只约束发送，状态可查询到收件箱被清理。收到 A.2 的 `queued` 时，客户端仍须保留待发送数据。

## 4. 稳定错误码

| 错误码 | 含义 | 可重试 |
| --- | --- | --- |
| `INVALID_REQUEST` | JSON、字段、类型或跨字段约束不合法 | 否 |
| `UNSUPPORTED_SCHEMA_VERSION` | 不支持的协议版本 | 否 |
| `AUTH_REQUIRED` | 缺少或无效的配对凭据 | 否 |
| `PAIRING_REQUIRED` | 设备尚未通过配对 | 否 |
| `PAIRING_EXPIRED` | 配对申请或凭据已过期 | 否 |
| `PAIRING_REJECTED` | 用户拒绝配对 | 否 |
| `SERVER_IDENTITY_MISMATCH` | 服务器证书指纹不匹配 | 否 |
| `PAIRING_RATE_LIMITED` | 配对尝试超过限制 | 等待后可重试 |
| `DEVICE_REVOKED` | 设备或凭据已撤销 | 否，需重新配对 |
| `MESSAGE_ID_CONFLICT` | 相同消息 ID 绑定了不同内容 | 否 |
| `MESSAGE_SEQUENCE_CONFLICT` | 同一设备/项目的序号冲突 | 否 |
| `MESSAGE_NOT_FOUND` | 查询的消息不存在 | 否 |
| `PAYLOAD_TOO_LARGE` | 请求体或正文超限 | 否，需缩小请求 |
| `RATE_LIMITED` | 消息或查询频率超过限制 | 等待后可重试 |
| `RETRY_WINDOW_EXPIRED` | 已超过 24 小时重试窗口 | 否 |
| `INTERNAL_ERROR` | 电脑端暂时无法完成请求 | 按响应属性决定 |

## 5. 凭据和数据生命周期

配对申请最多保留 10 分钟，处理完成、过期或拒绝后立即失效。凭据默认有效 90 天，电脑端可在撤销时提前终止，续期采用重新配对。电脑端收件箱只保存协议处理所需的设备 ID、消息 ID、项目 ID、序号、类型、正文、正文摘要、可选规格字段、原创建时间、接收时间、回执 ID 和状态。日志只记录消息 ID、状态变化、错误分类和时间。

## 6. 退出条件

`python scripts/verify-message-protocol.py` 必须通过全部合法、非法和边界夹具。Android 解析器必须使用同一目录中的夹具，拒绝相同的未知字段、重复键、超限正文、错误摘要和非法项目 ID。A.1 完成后，A.2 才可以实现监听服务，A.4 才可以在 Compose 中建立发送队列。
